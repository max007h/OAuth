## 4. Conclusion

### IAST : oui

Seeker est une bonne offre IAST. Il couvre l'instrumentation sans modification du code, le taint tracking source-sink, un faible taux de faux positifs, les bibliothèques réellement chargées, le déploiement on-premise complet et le blocage paramétrable du pipeline.

Les points faibles sont corrigeables :

- l'intégration GitLab passe par API REST, sans template natif ;
- les versions minimales Node.js et Python sont à vérifier sur le parc ;
- les données sensibles dans les findings doivent être maîtrisées ;
- les cotations CVSS, KEV et EPSS sont absentes.

### DAST : non

Tout le volet dynamique est "Sans objet" : crawling, découverte active, authentification du scanner, WAF, logique métier et corrélation DAST/IAST. L'éditeur dispose pourtant d'un DAST (Polaris fAST Dynamic, en SaaS), mais ne l'a pas proposé. Ce volet ne peut donc pas être évalué.

### Outil unique : non retenu en l'état

Un IAST seul ne peut pas être l'outil unique d'une banque :

- il ne voit que le code exécuté par les tests fonctionnels, donc sa détection dépend de la couverture QA ;
- il ne donne aucune vue attaquant : ni surface exposée, ni WAF, ni scan externe ;
- il ne couvre pas les applications non instrumentables (progiciels, applications tierces, langages non supportés).

Si l'objectif reste un outil unique, il faut un outil qui couvre au minimum le DAST. Black Duck ne répond pas à ce besoin tel qu'il a soumis.

### Recommandation

1. **Si l'outil unique est maintenu** : Black Duck est éliminé en l'état, sauf s'il complète son offre avec Polaris fAST Dynamic. Il faudrait alors une nouvelle évaluation DAST et une validation conformité du mode SaaS, puisque les résultats sont hébergés chez l'éditeur.
2. **Si deux outils sont acceptés** : Black Duck reste un candidat solide pour le lot IAST, à comparer aux autres soumissionnaires sur ce seul périmètre.

Question écrite à envoyer à l'éditeur : "Pourquoi le volet DAST n'a-t-il pas été proposé, et pouvez-vous le chiffrer ?"
